# Peer Review — Vectorised node representation (issue #26)

## Summary

The branch turns `MCTSNode` inside out as the story asks: child priors, visits and
total values move onto the parent as slot-indexed numpy arrays, PUCT selection becomes
one array computation plus `argmax`, child objects are materialised only when descent
first picks their slot, and the whole fleet's materialisations are resolved in a single
`apply_plies` call per wave. Every scope item in the story is delivered, all seven plan
steps are present (including the Step 7 README check), search results are pinned
unchanged by four benchmark signatures and two fixed-seed self-play ply sequences, and
the `apply_plies` seam drops from width `N × branching` to width `≤ N` with 4.5x fewer
position constructions on the wide cell.

`pyright` reports **0 errors, 0 warnings**; `ruff check .` reports **All checks passed**;
`pytest` is **241 passed**. No findings are filed from the tooling.

The substantive issue is not correctness but outcome: the recorded Step 6 measurement
shows all four benchmark cells regressing 29–78%, so the branch ships a slower engine
plus a new runtime dependency in service of a story motivated by speed. That is
analysed honestly in `benchmark.md` and deliberately not acted on per the plan, but it
is a decision that warrants an explicit sign-off rather than passing through a review
unremarked.

## Status

All twelve items are closed: ten fixed, one signed off (#1), one Will Not Fix (#7).
The sign-off and its reassessment trigger are recorded in `benchmark.md`. After the
fixes, `ruff check .` reports **All checks passed**, `pyright` **0 errors, 0 warnings,
0 informations**, and `pytest` is **242 passed** (241 plus the fleet mis-scatter test
added for #10).
